مدرسهٔ من — افزونهٔ پیام‌رسان

محتویات:
- messenger.html: پیام‌رسان مشترک
- برنامه هفتگی: مدیر در پنل مدیر برنامه را ثبت می‌کند؛ معلم در پنل معلم و دانش‌آموز در پنل دانش‌آموز همان برنامهٔ کلاس را می‌بینند.
- messenger-migration.sql: جداول، اعلان‌ها، مجوزها و کانال‌های پیش‌فرض
- صفحات اصلی سایت با میانبر پیام‌رسان

راه‌اندازی لازم (یک‌بار):
1) از فایل‌های فعلی مخزن GitHub یک نسخه پشتیبان داشته باشید.
2) در Supabase Dashboard > SQL Editor، ابتدا محتوای school-panels-migration.sql و سپس messenger-migration.sql را اجرا کنید (هر کدام جداگانه).
3) فایل‌های HTML را به ریشهٔ مخزن GitHub آپلود و Commit کنید.
4) ابتدا با یک حساب مدیر و یک حساب معلم آزمایش کنید.
5) اگر Realtime کار نکرد، در Supabase Database > Publications بررسی کنید جدول public.school_chat_messages در supabase_realtime باشد.

نکات امنیتی و محدودیت‌ها:
- این نسخه MVP پیام‌رسان است: کانال عمومی مدرسه، کانال معلمان، کانال مدیران، ارسال پیام متنی، به‌روزرسانی زنده و اعلان داخل برنامه.
- ایجاد کانال برای مدیر و معلم مجاز است؛ کانال مدیران فقط مدیر. دسترسی‌ها با RLS سمت دیتابیس محدود می‌شوند.
- برای دیدن پیام‌رسان، کاربر باید در همان مرورگر وارد حساب Supabase شود. اگر ورود در مرورگر جدید انجام شود، ابتدا از صفحهٔ ورود سایت وارد شوید.
- اعلان‌ها فعلاً داخل خود پیام‌رسان هستند، نه اعلان push وقتی سایت بسته است.
- پیام خصوصی یک‌به‌یک، فایل/عکس، واکنش‌ها، پاسخ به پیام، جست‌وجو، مسدودسازی و مدیریت اعضا هنوز پیاده‌سازی نشده‌اند و نیاز به توسعهٔ جداگانه دارند.
- هرگز Supabase service_role key را در HTML یا GitHub قرار ندهید.
- اجرای SQL نیاز به حساب دارای دسترسی مدیر پروژهٔ Supabase دارد؛ من آن را در پروژهٔ شما اجرا نکرده‌ام.


برنامه هفتگی:
- مدیر: از بخش «برنامه هفتگی» پایه، کلاس، روز، زنگ، درس و ساعت‌ها را ثبت می‌کند.
- معلم: در داشبورد کلاس تخصیص‌یافته را انتخاب می‌کند و از «برنامه هفتگی» برنامهٔ همان کلاس را می‌بیند.
- دانش‌آموز: در صفحهٔ خانه روی «برنامه هفتگی» می‌زند؛ برنامهٔ پایه و کلاس خودش نمایش داده می‌شود.
- جدول school_timetable و سیاست‌های دسترسی آن در school-panels-migration.sql تعریف شده‌اند.
